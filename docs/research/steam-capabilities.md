# Возможности альтернативного клиента Steam для macOS

Дополнение после исследования независимых клиентов: требование локального Steam runtime не означает обязательность официального desktop-приложения. OpenSteamClient хостит движок Valve собственным процессом. Для актуальной архитектуры см. [новый план](../standalone-client-plan.ru.md) и [исследование macOS runtime](macos-standalone-runtime.md). Ниже сохранён обзор публичных API, который сам по себе не охватывает private ClientAPI.

Проверено 9 октября 2026 года. Это исследование границ интеграции по публичным первичным источникам Valve; приложение и реальные аккаунты в рамках исследования не тестировались.

## Основной вывод

Собственный быстрый интерфейс библиотеки, нескольких аккаунтов, магазина и общения реалистичен. Обещание независимой замены Steam с **абсолютно всеми** функциями пока не подтверждается доступной документацией. Это инженерный вывод, а не утверждение, что независимая реализация технически невозможна.

Valve прямо документирует, что работающий Steam client предоставляет реализации Steamworks interfaces. Steamworks SDK подключает игру к клиенту и контексту AppID; он не является исходниками или автономной реализацией клиента. Инициализация также зависит от активного аккаунта, лицензии и ОС-пользователя. [Steamworks API Overview](https://partner.steamgames.com/doc/sdk/api).

Рекомендуемая архитектура продукта: собственные UI и модель данных; четко отделенные интеграционные адаптеры; официальный Steam для совместимости с играми; официальные веб-страницы для операций, не покрытых проверенной интеграцией. Независимый runtime — отдельное исследовательское направление с собственными критериями успеха.

**Существенная оговорка о производительности:** скрытое окно Steam не означает, что его процессы и webhelper перестанут потреблять ресурсы. Выигрыш гибридного решения надо измерять по суммарным CPU/RAM/energy всего дерева процессов и задержке взаимодействий. Официальный документированный headless-runtime, который можно просто встроить вместо Steam, в изученных материалах не найден.

## Три разных интерфейса

| Интерфейс | Что подтверждено | Следствие для проекта |
|---|---|---|
| Steamworks Web API | HTTP-методы бывают публичными и защищенными; часть предназначена для доверенных серверов издателя. | Нельзя считать любой найденный endpoint общедоступным пользовательским API. Ключ издателя нельзя распространять в приложении. [Web API Overview](https://partner.steamgames.com/doc/webapi_overview) |
| Steamworks SDK | API интеграции приложений со Steam; официальная библиотека macOS содержит x64 и arm64. | Rust/Swift FFI технически возможен, но не снимает зависимости от клиента и AppID. [API Overview](https://partner.steamgames.com/doc/sdk/api) |
| Клиентские сетевые протоколы и внутренние HTTP API | Полной публичной спецификации замены клиента в изученных источниках Valve не обнаружено. | Любой такой адаптер требует отдельного подтверждения поведения, оценки доступа и постоянного сопровождения. Наличие метода в protobuf или сторонней библиотеке само по себе не доказывает доступность и стабильность. |

## Матрица реализуемости

Уровни: **A** — собственная функция продукта; **B** — опора на документированный интерфейс с ограничениями; **C** — официальный Steam/веб-интерфейс как путь выполнения; **R&D** — самостоятельную реализацию нельзя обещать без прототипа.

| Функция | Уровень и рабочий путь | Граница / что проверить |
|---|---|---|
| Быстрая библиотека, поиск, фильтры, коллекции, теги | A: собственная локальная БД и UI; B: синхронизация доступных данных. | `GetOwnedGames` возвращает список только при доступности game details; скрытая библиотека не должна выглядеть как пустой аккаунт. [IPlayerService](https://partner.steamgames.com/doc/webapi/IPlayerService#GetOwnedGames) |
| Профили и друзья | B: `GetPlayerSummaries`, `GetFriendList`. | Приватный friends list возвращает 401; это не интерфейс постоянной синхронизации чата. [ISteamUser](https://partner.steamgames.com/doc/webapi/ISteamUser#GetFriendList) |
| Несколько аккаунтов в одном интерфейсе | A: раздельные записи, кэши и настройки. Авторизованные сессии — B/C/R&D в зависимости от адаптера. | Объединение представления библиотеки не объединяет лицензии, баланс, достижения или сохранения. Для каждой операции нужен явный account context. |
| Выбор аккаунта перед запуском | A: UI и правила выбора; C: выполнение через соответствующий активный Steam account. | Документированный универсальный API переключения активного аккаунта не найден. Надежное переключение без потери Cloud и запуска под прежним аккаунтом — отдельный прототип. |
| Запуск установленной игры | C: Steam launch path, включая `steam://run/<AppID>`. | Этот маршрут описан Valve. Прямой запуск бинарника не доказывает работоспособность Steamworks-функций. [API Overview](https://partner.steamgames.com/doc/sdk/api#SteamAPI_RestartAppIfNecessary) |
| Установка, обновления, проверка файлов, DLC | C первоначально; собственный менеджер — R&D. | Не смешивать доступ к файлам depot с полным жизненным циклом установленной игры. Steamworks `ISteamApps` — интерфейс информации об играх/DLC, не подтвержденная замена всего download manager. [API Reference](https://partner.steamgames.com/doc/api) |
| Каталог магазина | B для официального списка приложений; C для полной витрины. | `IStoreService/GetAppList` документирует каталог и маркеры изменения; из этого не следует наличие публичного универсального API всей персонализированной витрины и checkout. [IStoreService](https://partner.steamgames.com/doc/webapi/IStoreService) |
| Корзина, покупка игр, подарки, возвраты | C: официальный Steam Store/Support; встроенный web view только после проверки login/payment redirects. | Публичного документированного checkout API для покупки любых игр от имени пользователя в исследовании не найдено. `ISteamMicroTxn` — покупки предметов в игре издателя с его ключом, не Steam Store checkout. [ISteamMicroTxn](https://partner.steamgames.com/doc/webapi/ISteamMicroTxn#InitTxn) |
| Баланс и пополнение | C: страница кошелька Steam; собственное отображение — R&D до проверки источника. | Steam показывает текущий баланс после login. Нельзя превращать отсутствие подтвержденного источника в фиктивный «0». [Steam Wallet](https://store.steampowered.com/steamaccount/addfunds?l=english) |
| Текстовый чат | B ограниченно через SDK; C через официальный Steam Chat; независимый чат — R&D. | SDK содержит получение friend messages и `ReplyToFriendMessage`. Это не доказательство паритета истории, групп, вложений и voice. [ISteamFriends](https://partner.steamgames.com/doc/api/ISteamFriends#SetListenForFriendsMessages) |
| Группы, история, медиа и voice chat | C сначала; R&D для собственного UI/protocol adapter. | Valve подтверждает работу Steam Chat в браузере, но работа в конкретном WKWebView с mic, media и background events требует проверки. [Steam Chat Support](https://help.steampowered.com/en/wizard/HelpWithSteamIssue/?issueid=1004) |
| Приглашения в игру и присоединение | B в игровом AppID-контексте; C для совместимости. | `InviteUserToGame` приглашает в текущую игру. Принятие дает аргументы запуска либо callback уже работающей игре. Общий клиент должен проверить передачу обоих сценариев для разных игр. [ISteamFriends](https://partner.steamgames.com/doc/api/ISteamFriends#InviteUserToGame) |
| Lobbies и matchmaking | B для интеграции конкретной игры; C для существующих игр. | Lobby invitation может запускать игру с `+connect_lobby` или приходить callback. Наличие API создания lobby не делает launcher универсальным matchmaking backend чужих игр. [Matchmaking & Lobbies](https://partner.steamgames.com/doc/features/multiplayer/matchmaking) |
| Steam Cloud | C для существующих игр; R&D для независимой синхронизации. | Valve возлагает синхронизацию до/после игры на Steam client. У игр различаются API/Auto-Cloud, пути и platform mappings; неправильное переключение аккаунта способно перепутать локальные saves. [Steam Cloud](https://partner.steamgames.com/doc/features/cloud) |
| Workshop | C для загрузки/обновлений; B для части метаданных; независимый downloader — R&D. | Valve указывает, что загрузками управляет Steam client; есть legacy и ISteamUGC контент с разным поведением. [Workshop Implementation](https://partner.steamgames.com/doc/features/workshop/implementation#ItemInstallation) |
| Overlay | C; собственная замена — отдельный проект. | Официальный overlay внедряется в игры, запущенные через Steam, и поддерживает в том числе Metal/OpenGL. Скрыть основное окно — не заменить этот механизм. [Steam Overlay](https://partner.steamgames.com/doc/features/overlay) |
| Проверка лицензии / DRM / сторонний launcher | C для максимальной совместимости. | Valve описывает проверку владения и запуск Steam для DRM wrapper; конкретный механизм зависит от игры и платформы. Нельзя делать вывод «все macOS-игры используют wrapper», равно как «достаточно скачать файлы». [Steam DRM](https://partner.steamgames.com/doc/features/drm) |
| Remote Play / Together | C; самостоятельная реализация — R&D. | SDK дает game-facing session/invite функции, но это не готовый заменитель всей streaming-системы Steam. [Remote Play](https://partner.steamgames.com/doc/features/remoteplay), [ISteamRemotePlay](https://partner.steamgames.com/doc/api/ISteamRemotePlay) |
| Steam Families | C для управления и выбора копии; A для понятного отображения. | Families уже поддерживает выбор копии члена семьи и отдельный прогресс. Это отличается от смены аккаунта, под которым запускается игра. [Families FAQ](https://help.steampowered.com/en/faqs/view/054C-3167-DD7F-49D4) |
| Достижения, inventory, Trading, Market, Steam Input, Recording, VR | Декомпозировать; C как исходный маршрут. | Не считать закрытым требование «все функции» после запуска библиотеки/чата. Каждой подфункции нужны capability, проверяемый сценарий и fallback. Это рекомендация к scope, не заявление о невозможности их реализовать. |

## Авторизация: критические различия

1. **OpenID подтверждает личность.** Его документированный результат — SteamID, используемый для входа на сторонний сайт. Он не дает приложению пользовательскую store-cookie, сеанс сети Steam или универсальное право действовать от имени пользователя. [Authentication and Ownership](https://partner.steamgames.com/doc/features/auth#website).
2. **Steam OAuth не является свободно выдаваемой общей альтернативой OpenID.** Для Client ID надо обращаться в Valve. Документация описывает согласование permissions и AppID-scoped Cloud/Workshop; там же указано, что без сценария cross-platform Cloud или Workshop Client ID не предоставляют. [OAuth](https://partner.steamgames.com/doc/webapi_overview/oauth).
3. **Session tickets относятся к игре.** Они подтверждают пользователя и владение в игровых/backend-сценариях; для части методов нужен ключ, связанный с AppID. Это не общий login token альтернативного клиента. [Authentication and Ownership](https://partner.steamgames.com/doc/features/auth).

Практическое требование проекта: хранить для каждого аккаунта независимые состояния `identity`, `web_session`, `network_session`, `runtime_active`, `auth_required`; не считать один успешный вход доказательством готовности остальных слоев. Это архитектурная рекомендация.

## Мультиаккаунт: какой именно аккаунт выбирается

Нужно независимо моделировать:

- **Игрок** — чей SteamID получит игра, чей прогресс и друзья действуют в сессии.
- **Владелец лицензии** — чей экземпляр игры используется, включая Families.
- **Покупатель** — чей баланс, валюта и корзина участвуют в checkout.
- **Хранилище сохранений** — какие локальные файлы и Cloud-namespace относятся к запуску.

Steamworks позволяет игре отличать shared copy и получить владельца через `BIsSubscribedFromFamilySharing`/`GetAppOwner`; это не API переключения логина. [Steam Families для разработчиков](https://partner.steamgames.com/doc/features/families).

Families допускает выбор копии, а разный набор DLC способен повлиять на совместимость saves. Families рассчитан на домохозяйство до шести близких членов семьи и не делает все игры доступными для sharing. В UI собственного клиента нельзя скрывать эти ограничения или представлять лицензии как взаимозаменяемые. [Families FAQ](https://help.steampowered.com/en/faqs/view/054C-3167-DD7F-49D4).

Предлагаемый launch transaction: проверить game identity → выбрать игрока/лицензию → остановиться при чужой активной игровой сессии → дождаться завершения Cloud sync → переключить runtime → подтвердить активный SteamID → проверить совместимость DLC/saves → передать launch/invite → подтвердить фактический процесс и аккаунт. При неопределенном состоянии показывать причину и доступный официальный путь, не угадывать.

## Проверки, которые должны предшествовать обещаниям продукта

Это план экспериментов, а не выполненные испытания:

1. **Runtime prototype:** arm64 и x86_64 Mac, launch/exit, offline, overlay, achievements, Steamworks network game. Отдельно измерить ресурсы собственного UI и оставленного Steam.
2. **Account switching:** два собственных аккаунта, одна игра у обоих, разные DLC, разный Cloud, истекшая сессия, повторный Steam Guard, отмена переключения, reconnect. Нулевой допуск на запуск под ошибочным аккаунтом и перенос чужих saves.
3. **Commerce prototype:** официальный Store в WKWebView и системном браузере; логин, корзина, смена account context, wallet, платежные redirects/дополнительная аутентификация. Покупки проверять пользователем на конкретном согласованном заказе, не автоматическим тестовым списанием.
4. **Social prototype:** friend text, group chat, media, voice, invitation при закрытой/запущенной игре, cancel, timeout, смена аккаунта с ожидающим invite.
5. **Cloud/Workshop:** не добавлять свой writer до реализации журналирования, конфликтов, резервной копии и доказательства account isolation. Вначале наблюдение и управление через официальный клиент.
6. **Capability matrix:** для каждой функции фиксировать supported / delegated / experimental / unavailable, минимальные версии, тестовые игры, дату последней проверки и владельца поддержки.
7. **Доступ и распространение:** перед публичным выпуском отдельно проверить применимые условия Steam/Steamworks, лицензии зависимостей и право распространять необходимые компоненты. Это нерешенный вопрос проекта; из этой записки не следует юридический вывод о запрете либо разрешении альтернативного клиента.

## Рекомендуемый договор о полноте

«Все пользовательские сценарии доступны из одного приложения» и «все функции реализованы нами, официальный Steam не нужен» — разные требования. Первое можно планировать через собственный UI и явно обозначенные официальные пути выполнения. Второе нельзя оценить сроком обычной разработки интерфейса до завершения исследований runtime, авторизации, социальных протоколов, загрузок, Cloud и game compatibility.

Не следует считать наличие кнопки, открывающей Steam, полной собственной реализацией функции. В плане и интерфейсе происхождение действия должно оставаться прозрачным.
