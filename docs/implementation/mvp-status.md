## Shared library and compatibility extension (2026-10-09)

Implemented and covered by focused backend tests:

- Default library is `~/Library/Application Support/Steam/steamapps`; imported appmanifest paths are contained inside `common`. Initial read-only discovery found complete Brotato and Soundpad manifests, so no migration was needed. Soundpad was subsequently updated by the explicitly tested update operation.
- Installer supports native macOS and Windows depot selection. Update checks query public build IDs; incremental transfers seed staging from SHA1-verified chunks. ## Parallel download queue (2026-10-09)

The account-scoped scheduler supports 1–4 simultaneous games (default 2), pause/resume, cancellation with retained staging, retry, and queue reordering. Different games can transfer concurrently; the same destination and a running game's files remain reserved. Each game uses up to four concurrent chunk requests with serialized, awaited file writes. The SwiftUI Downloads page exposes the limit, controls, waiting-row arrows and drag reordering. Unfinished tasks restore paused after a client restart.

The reported THE FINALS stall was reproduced as CPU time in `seed_and_plan → Sha1::digest`: 314 staging files reserved 14,293,798,438 logical bytes with **zero allocated blocks**. The old installer hashed these sparse holes before requesting any payload. Planning now classifies new/unwritten ranges as missing, hashes existing data on the blocking pool, and reports disk verification separately. Development builds optimize hashing and decompression while retaining the requested file credential store.

`scripts/check-download-queue.py` tested the user's actual THE FINALS (`2073850`) and Raft (`648800`) downloads against Steam. Both received real network bytes concurrently. Pausing both stopped their byte counters; resuming Raft transferred more bytes, and cancel/retry worked. The test deliberately left these large downloads paused and did not complete either game. [Live control proof](../../outputs/download-queue-live-check.json).

The completion check caught and fixed an overlapping-depot regression in Soundpad: depot 629521 and 629522 contain different versions/sizes of the same DLL. Seeding all depots up front had allowed later writes to invalidate an already verified chunk plan. The installer now resolves the final per-path depot mapping before planning, downloading and calculating totals. A real failed repair and the passing retry are preserved separately; the successful retry verified and reused 16,818,875 bytes, committed the installation and retained the original correct DLL digest. It did not need additional network payload. [Before](../../outputs/download-integrity-regression-before.json), [after](../../outputs/download-integrity-regression-after.json).

Final checks: 38 core tests, 34 downloader tests, 20 Swift tests and workspace Clippy with warnings denied pass. Regression coverage includes pause during a stalled HTTP body, joined writes before releasing a slot, interruption versus atomic commit, shared-folder inventory ownership, sparse files, depot overlaps, account isolation, persisted cancellation intent, save-failure rollback and queue reordering.

The signed bundle was installed at `dist/SkinOS.app` with the previous app retained as a backup. Its UI restored the account and both paused downloads, displayed the 1–4 limit picker and per-game controls, and showed the completed Soundpad repair. THE FINALS was resumed via the UI. The user then began interacting with the app; at the last observation Raft was downloading at about 7.7% and THE FINALS was cancelled. Further UI control stopped to avoid interfering. Changing the picker through UI was not verified; the backend limit and reordering have automated coverage. [Packaged UI observations](../../outputs/download-queue-ui-check.json).

## Queue and installation removal (2026-10-09)

The Downloads row menu supports removing a record separately from cancellation or uninstalling. Active removal waits for transfer/writes to drain before its correlated acknowledgement; a committed installation remains installed. Removal intent persists across restart and failed saves do not falsely acknowledge deletion.

Installed game cards/properties request a server-side uninstall preview before showing confirmation. The preview lists directories and logical byte counts; a short-lived, single-use token binds execution to that plan, game, account and library. The filesystem transaction rechecks manifests, inode identities, file changes, shared-directory users and known partials under installer locks. It moves approved targets into private sibling directories before deleting them, rolls back pre-deletion failures, and reports retained paths on a later filesystem error. Core refreshes installed state on either outcome.

Shared Counter-Strike/Half-Life files stay in place while the other manifest needs them; the selected appmanifest is removed. Legacy `SkinOs/games/<appid>` copies appear explicitly in the plan and are removed too, preventing the old fallback from making an uninstalled game reappear. External saves, CrossOver prefixes and previous recovery backups are retained. Mods/saves inside removed game directories are deleted, as stated in confirmation.

Validation: 45 core tests (including queue removal, races/persistence and confirmation scope), 27 Swift tests, and 12 filesystem-removal fixtures pass, plus strict workspace Clippy. Filesystem deletion tests use temporary fixtures only. Real read-only previews covered Counter-Strike (shared with AppID 70), both Brotato copies, and Soundpad. [Actual preview scopes](../../outputs/uninstall-preview-check.json). No user game was uninstalled for testing.

The removal build was installed and opened at `dist/SkinOS.app`. Its real Downloads menu showed «Убрать из очереди», and the Soundpad card opened a native confirmation with its exact path and 16.8 MB. The dialog was cancelled and Soundpad remained installed. ## Raft fresh-prefix launch fix

Raft (`648800`) reproduced `sdk_classic_init_failed` before the game started, despite native runtime authentication, subscription and install-state checks passing. Its original x64 SDK and AppID were correct, but the newly created Wine prefix lacked `SteamPath`, `SteamClientDll64` and `ActiveProcess`. Older Counter-Strike and Soundpad prefixes already had these keys, masking the issue. The SDK probe had used NotProton `runinprefix`, which skips its Steam shim bootstrap.

The probe now uses the same foreground `waitforexitandrun` path as the game. The bundled compatibility shim initializes the prefix and preserves child stdout/exit status; game DLLs, real SDK verification and the owned Valve runtime remain unchanged. The old command failed; the new packaged core initialized Raft's genuine `SteamAPI_Init`, returned matching online identity, launched the game for **63.17 seconds** and stopped it cleanly. The user confirmed the menu. Runtime exit code was 0 with clean release, no timeout, and no original Steam GUI appeared. The three previously missing registry entries were created by the normal launcher, with no manual registry edits. Seven compatibility tests and strict workspace Clippy passed.

- The dynamic adapter is audited for arm64 and runtime SHA-256
  `035722a42c74989fa38c7efe0d735fdb38444e1102c92246652b5d913d019840`.
  Unknown runtime fingerprints are rejected. Brotato's passing run is not a
  compatibility guarantee for every Steam game.
- Runtime acquisition uses the separately staged SkinOs-owned
  `runtime-source/current.json` and private copies. There is no automatic
  fallback to original Steam state or binaries when the private source is absent.
- Steam Cloud is explicitly disabled in the experimental private runtime.
  Overlay, broad multiplayer/anti-cheat compatibility and full Steam feature
  parity remain outside the completed verification. Store/profile authentication

The neutral SDL fixture is discovered by the owned Valve host, but the game-facing API still returns no handles. Physical hardware is deferred by the user. See [current evidence](steam-input-host.md).
- Downloads and one running game now have independent operation locks. The same game cannot be updated while SkinOS is running it. This replaces the earlier MVP-wide operation lock; the historical Brotato UI proof predates this extension.

## Development credential store

The debug core now stores its own refresh token in `SkinOs/credentials` (0700 directory, 0600 atomic token file), following the user's request to avoid repeated Keychain prompts during rebuilds. Release defaults remain Keychain unless `SKINOS_CREDENTIAL_STORE=file` is explicitly set. A migration-attempt marker allows at most one lazy import from SkinOs's own Keychain record. Cancelling that attempt or forgetting the local account cannot repeatedly prompt or resurrect the old token; signing in again creates a new local record. No Steam password or macOS password is stored.

The real development session has been migrated once; directory/file permissions were verified as 0700/0600, and subsequent rebuilt-core authentication used the file without another Keychain prompt. File-store tests use test-only fake tokens and injected migration closures. They cover permissions, round trips, default/override selection, one-time migration, cancellation, forgetting, and symlink rejection. These tests never read real Keychain data.
